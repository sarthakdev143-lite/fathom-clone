## Your actual problem: the app only records your mic

`getUserMedia({audio: true})` captures the **input device only**. So the app records you and whatever else is physically in the room. 1. **Tab audio capture** (`getDisplayMedia({audio:true})`) — the only in-browser option. 2. **OS loopback** — WASAPI on Windows, BlackHole on macOS, PulseAudio monitor on Linux. Captures the mixed system output, so it gets the remote side. But it needs a desktop app or browser extension; a web page cannot reach it. This is what real meeting tools do.
3. **Second device on the table** — works today via the existing upload path, no code.

Clicking a line or moment also **starts playback**, not just jumps there. That matches how Otter and Fathom behave, but it's one line to change if you only want the jump. Auto-scroll only moves the transcript box, never the whole page, so someone reading the summary doesn't get dragged down. The one exception is opening a `?t=` link, where showing that line is the point.
