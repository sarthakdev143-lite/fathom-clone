## #2 Tests
- **103 tests**, run with `npm test`. Each test file gets its own temporary SQLite database and a faked network, so no API keys are needed and nothing touches production.
- They cover parsing, windowing, provider retry and fallback, the blob URL safety check, leases, rate limits, cleanup, the client retry loop, and real ffmpeg splitting of an encoded WebM file.
- CI in `.github/workflows/ci.yml` runs typecheck, lint, tests and build on every push and PR.

## #3 Length caps removed
- **Transcription:** audio over 14 MB is split with ffmpeg into ~15-minute pieces, each transcribed separately and put back on one timeline (`src/lib/transcribe.ts`). Cuts go in the nearest pause: a fixed cut turned "rules engine" into "rules and | engine" in testing.
- **Summaries:** no more sampling. Long transcripts are summarised in sections and then merged, and key moments are moved onto real transcript lines.
- **Long requests:** both steps save progress after each piece and return 202 so the browser calls again. A request killed by Vercel's time limit carries on where it stopped.
- **Upload limit:** raised from 100 MB to 200 MB.
- **Live mode:** the ceiling goes from 20 minutes to 3 hours.
  - After a while the live summary only sends new text plus the previous summary, so calls stay the same size.
  - Captions are sent less often as the meeting goes on.
  - Audio slices are downsampled to 16 kHz.
  - A 30-minute meeting now makes about 220 caption calls instead of 300.

## #4 Reliability
- **Retry buttons** on the meeting page for every stuck state, including "Summarize partial transcript" for an interrupted recording.
- **Processing lock**, so two requests never work on the same meeting at once.
- **Cleanup:** recordings abandoned mid-session and processing that stalled are marked failed, with any partial work kept. This runs on page loads and daily from a Vercel cron job, which also deletes unreferenced uploaded audio older than a day.
- **Bad JSON from the model:** Groq's `json_validate_failed` error and wrong-shaped replies are now retried (up to 3 attempts) instead of failing the meeting.
- **Per-IP rate limits** on every endpoint that costs money or storage.
- **Monitoring:** structured JSON logs, logging of unhandled errors, and a `GET /api/health` endpoint.

## Existing bugs found and fixed along the way
- The "no provider configured" check (`!hasGeminiKey`) in three routes could never trigger.
- With the Groq key missing, the app retried 5 times (~15 s) before switching to Gemini.
- The recorder reference was never set, so Stop only worked indirectly.
- On a fresh clone, `db.ts` failed on the first request because it didn't create the `data/` folder.
- Two cold starts running the same migration at once failed a request.

- A 37,000-character transcript was summarised in 3 sections plus a merge in 128 s. Groq's 8,000 tokens-per-minute limit was waited out automatically.
- Every key moment landed on a real transcript line.
